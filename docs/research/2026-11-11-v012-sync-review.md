## 1. Think panel double-display fix — `67b3ec458`

**Symptom** (user report): "think panel 现在总会显示。就是同时显示 7 行和 1 行的 think" —
7 rows = activity panel band; 1 row = transcript's collapsed "Thinking..." placeholder.

**Mechanism** (verified in-tree):
- With `hideThinkingBlock: true`, the transcript renders each hidden thinking run as a
  one-line label — `packages/coding-agent/src/modes/interactive/components/assistant-message.ts:188-195`
  (`hidden = overrides ?? this.hideThinkingBlock`; hidden runs render
  `theme.fg("thinkingText", this.hiddenThinkingLabel)`).
- The panel's 7-row band shows the live thinking simultaneously → 7+1 on screen, and the
  placeholder persists in history after the turn settles.

**Fix** (activity-panel.ts:223-227, 263-264, 354, 378): while the panel is enabled,
`ctx.ui.setHiddenThinkingLabel("")`; `/activity off` and `session_shutdown` restore
`undefined`.

**Findings — all PASS:**
1. Empty label renders zero rows *including no spacing* — proven at
   `assistant-message.ts:189-192`: `if (hidden && !this.hiddenThinkingLabel.trim()) continue;`
   (the in-tree implementation of upstream #11470).
2. **Cannot swallow the native thinking stream when `hideThinkingBlock: false`**: the
   label is consulted only on the `hidden` branch (`:188-196`); visible runs render the
   full markdown block and never read `hiddenThinkingLabel`. Per-run expand overrides
   (`thinkingVisibilityOverrides`, `:188`) are likewise unaffected.
3. `undefined` restores stock: `interactive-mode.ts:2522-2523`
   (`label ?? this.defaultHiddenThinkingLabel`), propagated to children and the
   streaming component (`:2524-2531`).
4. Multi-session / switch ordering: `switchSession` teardown emits `session_shutdown`
   (restore) → `beforeSessionInvalidate` → `resetExtensionUI()` also resets the label
   (`interactive-mode.ts:2622`) → new `session_start` re-applies. Both reset points run
   *before* the extension's `session_start` handler, so the blank survives switches.
5. `/activity` ordering: `enabled`/`rows` mutate before `applyTranscriptThinkingVisibility`
   (`activity-panel.ts:367-378`), so the applied label always matches the just-set state.
6. `session_start` applies twice — sync (in-memory `enabled`), then after `loadConfig()`
   (`:263-264`). Worst case on first boot with on-disk `enabled:false` is a one-tick
   mislabel, immediately corrected. Non-TUI modes hit the no-op stub
   (`core/extensions/runner.ts:341`). Handler exceptions are impossible here
   (synchronous body, `loadConfig` catches internally).

**Residual (P2, pre-existing, NOT a regression):** with `hideThinkingBlock: false`
(the default, `core/settings-defaults.ts:27`) and the panel on, thinking still shows
twice (full transcript blocks + panel band). The fork does not force the setting
(grep: zero hits in `src/experimental/durable-tui/`). The fix targets the reported
hidden-label case only. Suggestion: document "hide thinking (ctrl+t) for the
single-view experience" in the panel docs, or auto-suggest on first enable.

## 5. Fork behavior ruling (decision item): keep "cancel + stay", do NOT map fork → new session

Rationale:
1. **Honesty.** Upstream's label promises "Fork into <cwd> (new session ID, original
   kept)". The durable factory's `"new"` branch (`main.ts:246`) creates an *empty*
   session — mapping fork→new would silently discard the history the user asked to
   fork. A truthful "not supported yet (planned)" beats a lying success.
2. **Consistency with the established stance.** The factory already refuses fork
   (`main.ts:242-243`, unchanged since the 1.5.0 line). The guard extends that refusal
   to *before* teardown; the factory remains defense in depth. Two different fork
   behaviors at two layers would be worse than either alone.
3. **1.5.2 semantics don't transfer.** Upstream fork is a JSONL-file operation
   (`SessionManager.forkFrom`). A durable fork needs a store-level copy-up-to-entry —
   that is the planned feature. Faking it with a JSONL fork file creates exactly the
   cross-store hybrid the factory refuses.
4. **No user is stranded.** Cancel keeps the live session fully usable; the picker's
   own sessions keep working; the upstream prompt's other choices behave sanely (§4).
