## Ruling 2 — think display: yield (shipped) beats panel-priority

`8dacad0c1` · `packages/coding-agent/src/experimental/durable-tui/activity-panel.ts`

The shipped behavior — with `hideThinkingBlock: false` the panel renders 0 rows during thinking and the think→tool bridge (`bandRows` gate at :158) — is the correct call. This is not user-taste; it is correctness:

1. `hideThinkingBlock` is the user's explicit display contract (upstream default `false`, `settings-defaults.ts:27`). Panel-priority would *silently suppress content the user asked to see* and substitute the band's truncated tail window (`MAX_RETAINED_CHARS`) for the full native block. Yield keeps full fidelity; the panel only owns thinking when the transcript renders none (`hideThinkingBlock: true` → placeholder, already blanked since 0.12.0).
2. Consistent with the extension's own stated ownership rule ("panel owns LIVE tool display"; thinking ownership was always conditional).
3. v3 semantics are self-consistent: `bandRows` already returns `[]` for idle/disabled (:152), so 0-row render is an existing path; the fixed-height contract is "exactly `rows` lines *while visible*" (:144-146) and yield = not visible. The 1s reply hide gate arms on `text_` events regardless of rendered rows; `tool_execution_start` clears it and re-shows the 🔧 band with fixed geometry. Hiding the done-from-think band under native display is right (it would be a second thinking summary).
4. Toggle timing is sound: the host toggle persists synchronously (`setHideThinkingBlock` → `save()`, `settings-manager.ts:629,986-990`), and the panel re-reads only on *entry* into a thinking phase (`activity-panel.ts:321`, guarded by `mode !== "thinking"` so no per-chunk I/O) plus `session_start` (:295). Live toggle → next phase. Phases without thinking never consult the value — correct, it only gates thinking display.

Residual product note (taste, for a future explicit panel setting — not this commit): default-config users lose the persistent elapsed-time affordance during thinking. If wanted, add a panel config option later; do not flip the default here.

## Findings

### P1 — Panel reads settings from its own file pass instead of the host's effective settings

`activity-panel.ts:252-256` builds `SettingsManager.create(cwd, getAgentDir())`, whose `projectTrusted` defaults to **true** (`settings-manager.ts:335`). The host's runtime manager is created with the *real* trust decision (`main.ts:809-810`, `SettingsManager.create(cwd, agentDir, { projectTrusted })`). Divergence case: an untrusted project whose `.pi/settings.json` sets `hideThinkingBlock: true` while global is unset → host streams the native block (effective false) while the panel reads true → 🧠 band + native block = the double-display bug this commit fixes, resurfacing in that config. `ExtensionAPI.getSettings(): Settings` already returns the host's effective merged settings (`core/extensions/types.ts:1821`) — use it in `refreshNativeThinkingVisible` instead. ~3-line change; recommended for v0.12.1, not blocking (requires project settings + declined trust to trigger).

### P2 — Refused durable-tui /import leaves an empty default session dir

`getDefaultSessionDir` mkdirs as a side effect (`session-manager.ts:597-601`) and runs *before* `emitBeforeSwitch` (`agent-session-runtime.ts:370-374` vs :385), so a guard-cancelled import still creates `~/.pi/agent/sessions/--<cwd>--/` (empty). Benign — plain pi in that cwd creates it anyway; no session file is written (guard precedes `copyFileSync` :392). Optional follow-up: hoist the guard above dir resolution; low value vs upstream-sync cost. Also note the `existsSync/mkdirSync` at :372-374 is dead code in the fallback branch (getDefaultSessionDir already mkdirs) — harmless.

### P2 — No committed regression test for the yield path

`8dacad0c1` touches only `activity-panel.ts`; the 19/19 mock frame-by-frame run was scratch (not in tree — verified: no test imports `experimental/durable-tui/activity-panel`). The `nativeThinkingVisible` gate (:79, :158, :252-256, :295, :321) can silently regress in a future refactor. Commit a small unit test of the mode machine + gate when convenient.

### P2 — Refresh-failure fallback restores the old bug shape

On any settings read failure the panel keeps panel-owned thinking (:256, `nativeThinkingVisible = false`), which under `hideThinkingBlock: false` reproduces double-display. Exception-only path; acceptable. The P1 fix (getSettings) also shrinks this surface.
